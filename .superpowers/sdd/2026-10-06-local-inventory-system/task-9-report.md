# Task 9 — Packaging, E2E, handoff, and release report

Date: 2026-10-07
Branch: `feature/inventory-desktop`
Starting commit: `7695a38`

## RED evidence

The full Electron E2E test was written before its lifecycle/package hooks. The first `npm run test:e2e` failed with `Missing script: "test:e2e"`. After wiring Playwright and the Forge package step, the test reached Electron but timed out waiting for its first window. Launch diagnostics identified two app packaging defects: Vite had bundled `better-sqlite3` such that its native `.node` module could not be required, and the renderer was emitted beneath `src/renderer/.vite/` while the packaged main process loaded `.vite/renderer/`. The E2E test also caught a fixture that tried to transfer a pack when only 52 pieces remained at the source.

## GREEN implementation

- Kept `better-sqlite3` external from the Vite main bundle and set the renderer build output to the path that the packaged main process loads.
- Added development-only E2E lifecycle seams: the app can use `SIOMAI_E2E_USER_DATA`, and report export can write to `SIOMAI_E2E_EXPORT_PATH`. The seams are gated by `!app.isPackaged`; production keeps native save dialogs and the normal Application Support location.
- Added the Playwright/Electron scenario for rendered first-run setup, opening stock, piece and pack sales, location creation, transfer, count discrepancy, report CSV export, app restart, persisted balances, sale void, and manual backup. It drives the renderer screens and uses the typed preload API only to inspect persisted results. It sets up 500 opening pieces so the selected pack transfer is valid.
- Added Forge macOS metadata for bundle ID `com.siomai.inventory`, `LSMinimumSystemVersion` 13.0.0, app category and ICNS icon. Signing identity, hardened runtime, entitlements, and notarization credentials are environment-driven.
- Added valid ICNS and PNG assets generated by `scripts/create-assets.mjs`; the DMG background and icon are not renamed placeholders.
- Added a package checker that opens the produced ASAR and checks packaged metadata, CSP directives, development URLs, credential file/key patterns, and any supplied signing-secret values. On a macOS `.app`, it additionally checks `Info.plist`, bundle ID, minimum OS version, and the installed ICNS.
- Added a tag-triggered macOS workflow using Forge's universal architecture target. It checks required secrets, installs the P12 in a temporary keychain, runs project checks, builds the universal DMG, submits app and DMG for notarization, staples, verifies `codesign` and Gatekeeper, checks both binary architectures, and uploads the DMG with its SHA-256 file.
- Added operator, release/recovery, and acceptance documents, plus release notes and README.

- Package checks operate on the archive Forge actually produced, not just source configuration. CI supplies signing secrets to the checker so accidental inclusion is compared against actual values without printing them.
- E2E native save-dialog substitution is available only when the app is unpackaged and `SIOMAI_E2E=1`; the normal packaged UI path still opens the operating-system save dialog.
- The release artifact is a universal app generated through Forge's `--arch=universal` path, not a claim that this Linux run built or signed a DMG.
- The release depends on the client's certificate and App Store Connect credentials. Those credentials are not present in the repository, docs, app archive, or local verification output.
- macOS signing, notarization, stapling, and client-machine acceptance remain pending external execution; the current development package is not the client installer.
